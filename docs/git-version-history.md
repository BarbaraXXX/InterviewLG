# Git 版本提交记录

本文档用于记录项目每次关键 git 版本提交的主要内容，方便后续溯源、复盘和个人总结。

记录原则：

- 重点记录功能变化、架构变化、部署影响、数据/安全/资源影响。
- 不逐字复制 commit message，而是记录“为什么改、改了什么、影响什么”。
- 小修复可以归入最近的未发布记录；正式打版本时再整理到对应版本。
- 后续每次完成较完整的功能、修复或版本发布后，应同步更新本文档。

## v1.14.0

主题：问砺品牌、公开产品首页与前端视觉层级重构。

### 产品品牌与公开首页

- 产品对外名称由 `InterviewLG` 更新为“问砺”，品牌副标统一为“AI 技术面试训练”；新增对话气泡与连续追问轨迹组成的 SVG 标志和 favicon。
- 根路径 `/` 从鉴权后自动跳转入口改为公开产品首页，未登录用户无需等待 `/api/auth/me` 即可直接了解产品。
- 首页围绕“把掌握的知识，练成面试现场能说清楚的回答”组织内容，依次介绍训练流程、6 / 10 / 15 题挡位、核心能力、产品真实边界、数据与隐私、常见问题和开始入口。
- 首页只陈述当前已实现能力，明确代码区不在线编译、能力报告尚未上线、AI 输出不代表招聘结论，不使用虚构用户数、评价、通过率或合作品牌。
- 已登录浏览器返回首页时主入口显示“进入工作台”；未登录用户从“开始模拟面试”进入 `/login?next=/setup`。

影响：

- 不修改仓库名、Python 包名、Docker 服务名、Cookie 名或既有浏览器存储键，避免部署路径和已有登录状态失效。
- 管理后台入口、权限模型与聚合数据范围保持不变，只同步使用新的对外品牌标识。

### 路由拆包与认证体验

- 原 4,000 余行应用入口机械迁移到 `app/Application.tsx`，新的 `App.tsx` 只负责公开首页和业务应用的路由边界。
- 公开首页使用独立 CSS Module；现有业务样式仅随 `Application` 动态加载，Markdown / KaTeX 只在聊天或历史内容出现时加载，代码编辑器继续二级懒加载。
- 生产构建验证公开首页首屏不再加载完整应用样式、Markdown / KaTeX 或 CodeMirror；初始脚本约 262 KB（gzip 约 84 KB），登录工作区 JavaScript 约 122 KB，Markdown 与代码编辑器继续延迟加载。
- 受保护顶层页及 `/interview/:sessionId`、`/history/:sessionId` 深链会把安全的本站路径写入 `next` 参数；登录成功后恢复原目标。
- 登录返回地址拒绝绝对 URL、协议相对 URL、管理员路由、未知路由、反斜杠变体和畸形编码，避免开放重定向。
- 退出登录后回到公开首页；已登录访问 `/login` 时进入安全解析后的目标页或工作台。
- 登录态增加代际隔离：过期时清空内存中的会话、消息和进度，晚到的旧 heartbeat / SSE 401 不能再覆盖新的登录态或向新账号展示旧账号缓存。
- 简历、岗位偏好和会话列表的缓存与并发请求绑定认证 epoch；账号切换后不会复用旧 Promise，旧请求晚到也不能回写新账号缓存或触发导航。
- 退出登录只有在服务端确认清除 HttpOnly Cookie 后才清理本地状态；网络或服务异常时保留当前页面并明确提示重试。

影响：

- `/dashboard` 继续作为登录后的工作台，现有面试、历史详情和调试参数路由不变。
- 公开首页不发起认证或业务 API 请求，降低访客首屏对后端状态和小服务器资源的依赖。

### 视觉系统、认证页与可访问性

- 统一翡翠绿与青蓝品牌色，补齐此前缺失的 surface、muted text、success 和小圆角变量，并把圆角层级调整为 4 / 7 / 11 / 16 / 24 像素。
- 页面背景增加低对比网格与静态光晕，Surface 明确区分普通、抬升和浮层层级；配置页不再用纯色背景遮住全局画布。
- 登录注册页去除旧的功能数字卡片，改为品牌叙事、连续追问示意和聚焦认证的双栏结构；移动端先展示表单，再展示产品说明。
- 登录和注册切换增加 `aria-pressed`，输入框补齐 autocomplete，异步状态使用 `aria-live`；共享主题按钮和品牌标志都有可访问名称与清晰键盘焦点。
- 主题状态统一由顶层应用维护，Landing、普通用户端和管理端共享同一状态；从登录页或工作台返回首页不会再恢复成旧主题。
- 主题在 React 首次绘制前由同源静态脚本恢复，兼容生产 CSP，不引入第三方字体、图片或动画依赖。
- 浏览器验证深浅主题以及 375、768、1024、1440 像素宽度，无横向溢出和控制台错误；所有动效遵循 `prefers-reduced-motion`。

影响：

- 本版本是纯前端和文档迭代，不新增数据库迁移、后端接口、模型调用或生产服务。
- 前端单元测试从 26 项增加到 43 项，新增品牌、主题、首页内容、公开/受保护路由、安全返回地址、退出失败和跨账号缓存隔离覆盖。

## v1.13.0

主题：以问题预算驱动的可控模拟面试。

### Interview Blueprint 与问题挡位

- 新增 schema v1 的 `InterviewBlueprint`，每个新会话在创建事务中持久化问题挡位、面试强度、训练重点、总问题预算、是否包含手撕和各阶段预算。
- 新增三档问题预算：精简 6 题（开场 1 / 项目 2 / 技术 3 / 手撕 0）、标准 10 题（1 / 3 / 4 / 2）、深入 15 题（1 / 5 / 6 / 3）。
- 标准和深入档固定包含手撕代码；精简档将 coding 阶段标记为 skipped，并拒绝代码工具绕过计划创建题目。
- 新增引导型、标准型、压力型三种强度；支持最多两个训练重点：项目深挖、技术基础、系统设计、编码能力、表达与思路。
- 最近一次面试配置同步保存挡位、强度和重点，再次配置时可以完整恢复。

影响：

- 新增 `session_blueprints` 表，以及 `session_states.answered_questions`、最近配置的挡位/强度/重点字段；迁移幂等，不修改原始消息和历史会话内容。
- 历史会话不回填 Blueprint，继续使用旧阶段逻辑，对外返回空计划与空进度。
- Tester 不做功能改造，只随项目统一版本号。

### 权威阶段 Controller 与会话结束

- Blueprint 会话的阶段改由问题预算确定性推进，状态评估器继续记录 Topic 和回答质量，但不能自行改变阶段。
- `answered_questions` 与普通聊天轮次分离：普通回答和代码提交计 1；active 代码题期间请求提示或澄清不消耗题额。
- 总结阶段只允许输出最终评价，不得继续提问或调用代码工具，且要求结束语只出现一次。
- 总结回复保存后由服务端幂等完成会话、记录完成指标并触发长期记忆更新，不再只依赖前端识别结束短语。
- 已有 active turn 时暂停、结束和删除返回 409；前端在取消流后短暂重试暂停/结束操作，避免状态写入竞态。
- 已完成 Topic 可显式记录其被回答时所属阶段，避免阶段切换边界把项目问题误记到技术阶段。

影响：

- 暂停和用户思考时长不会影响面试挡位。
- 标准模式默认按完整的项目、技术、手撕、总结路径推进。
- 会话暂停、恢复和页面刷新后继续使用数据库中的原 Blueprint 与题数进度。

### 失败回滚、进度 API 与界面

- 流式回复生成前保存状态快照；模型失败、空回复或客户端中断时，原子删除本轮新增消息并恢复阶段、Topic、轮次和题数。
- 用户消息和 AI 回复在成功完成后统一执行历史保留裁剪，失败轮次不会误删最早历史消息。
- 创建会话、会话详情和恢复接口返回 Blueprint 与进度；新增会话进度查询接口。
- 配置页新增独立“面试策略”步骤，聊天页展示当前阶段、已完成/总题数和进度条；阶段和题数同时使用文字与视觉反馈，不只依赖颜色。
- 浏览器实际验证桌面、768px 和 375px 视口，修复移动端 Grid 最小内容宽度造成的横向溢出，并优化平板端聊天头部布局。

影响：

- 新增进度查询只读取单场 Blueprint 与 session state，不引入轮询；仅在进入聊天页和每轮完成后刷新。
- 旧会话没有 Blueprint 时不展示进度，不影响历史回看和继续面试。

## v1.12.0

主题：RAG 召回正确性、面试轮次一致性与工程门禁。

### RAG embedding 一致性与召回质量

- 生产环境核查发现：现有 QuestionCard 索引由 `dashscope:text-embedding-v4` 生成，但运行时缺少 Embedding Provider 与 Key，查询侧回退到 deterministic 哈希向量，导致查询向量和索引向量不在同一空间。
- QuestionCard 与 CodingProblem Store 新增 embedding readiness 检查，校验运行时 Provider、模型、维度和索引元数据；不一致时健康检查和检索接口返回 503，不再静默注入错误结果。
- RAG query 只保留真实候选人/面试官消息，排除面试状态、阶段控制、用户记忆和滚动摘要等内部 SystemMessage。
- 使用正确的 DashScope 查询向量对生产索引标定：Redis、Go GMP、RAG 混合检索的首条相关分分别为 0.868、0.798、0.874，库内缺少对应内容的连接池查询最高为 0.566；据此将默认 `RAG_MIN_SCORE` 调整为 0.65。
- 部署配置增加 Embedding Provider/Key 校验；配置缺失时部署脚本提前失败，避免服务启动后才发现题库不可用。

影响：

- 不修改或重建现有 QuestionCard、CodingProblem SQLite 数据，只要求运行时查询配置与索引一致。
- 缺少匹配卡片或得分低于阈值时自动回退为无 RAG 上下文的面试，不影响主对话可用性。
- VectorDB 健康检查会读取少量索引元数据，但不会执行 embedding 请求或全量向量扫描。

### 单会话轮次与消息一致性

- 新增 session 级轮次协调器，同一 session 同时只能运行一个 Agent turn；来自重复标签页或并发请求的第二轮会返回 409。
- 消息序号改为 SQLite `BEGIN IMMEDIATE` 事务内读取并写入，避免 `MAX(seq)` 与 INSERT 分属不同连接造成竞态。
- 消息表新增 `(session_id, seq)` 唯一索引；初始化检测到历史重复时，会先按原 `seq, id` 顺序重新编号，再创建索引。
- Agent 回复保存后同步完成本轮状态评估，再发送 SSE `done`；下一轮不再读取到上一轮尚未落库的阶段与 Topic 状态。
- SSE 正常完成、异常或客户端中断都会释放 session turn 锁，避免会话永久处于 busy 状态。

影响：

- 不改变消息正文、用户账号、简历、代码提交和会话归属。
- 状态评估发生在回复 token 输出结束与 `done` 之间，前端会等待状态落库后重新允许输入。
- 生产核查未发现重复消息序号；迁移逻辑主要用于防止后续并发写入。

### 工程检查与版本统一

- `rag-data-pipeline` 新增独立 `pyproject.toml`、`uv.lock`、Ruff 和 pytest 配置，不再依赖手工 `PYTHONPATH=src` 才能测试。
- RAG pipeline 纳入 `scripts/check.sh` 和 GitHub Actions；前端现有 Node 单元测试也纳入本地一键检查和 CI。
- 统一 Agent、VectorDB、Tester、RAG pipeline、前端包和页面展示版本到 `v1.12.0`。

影响：

- 不新增生产容器和运行时依赖；RAG pipeline 仍是离线工具。
- CI 增加 19 项 RAG pipeline 测试和 21 项前端测试，提交检查时间会小幅增加。

## v1.11.0

主题：小规模内测前稳定性、版本统一与调试准备。

### 版本统一与部署准备

- 统一前端展示版本、前端 `package.json`/`package-lock.json` 和后端 Python 包版本到 `v1.11.0`，减少部署排查时出现多个版本号的问题。
- 移除前端 HTML 中的 Google Fonts 远程字体加载，改为系统字体栈，避免生产 CSP `font-src 'self'` 与远程字体 CSS 冲突。
- 保持 CSP 不额外放宽到 Google Fonts 域名，降低外部资源依赖和被浏览器拦截的概率。
- 按 2 核 4G 服务器调整 Docker Compose 资源限制：app 容器提高到 2G/1.5 CPU，vectordb 提高到 1G/0.5 CPU，并给 nginx、certbot、系统和 swap 留出余量。

影响：

- 不改变数据库结构、用户数据、面试记录、Agent 主流程和服务数量。
- 生产页面不再依赖远程字体 CSS，加载更稳定。
- 容器资源上限更贴合当前服务器规格，但仍不会允许主服务吃满整机资源。

### 出题原因调试面板

- 新增调试模式下的 `emit_question_rationale` 工具，Agent 在提出问题或追问前可输出公开版出题原因。
- 调试功能采用两层控制：后端 `QUESTION_RATIONALE_ENABLED=true` 总开关，前端 URL `?debug_rationale=1` 会话开关；两者同时满足才启用。
- 出题原因通过 SSE `question_rationale` 临时发送到前端 Debug 面板，不写入面试消息、历史记录或数据库。
- 前端聊天页新增调试 Timeline，展示阶段、主题、触发原因、考察目标和观察点；普通用户不带调试参数时不显示。
- 同一 session 的内存 Agent 会按调试状态重建，避免普通模式复用带调试工具的 Agent。

影响：

- 默认关闭，不影响普通用户、线上面试流程、历史记录和数据库结构。
- 开启调试时每个问题可能多一次工具调用和少量 token/SSE 事件，适合开发排查，不建议长期面向普通用户开启。

### 前端限流与认证路由误跳修复

- 修复频繁进入历史记录或快速点击刷新时，前端重复请求 `/api/sessions?limit=100` 导致 Nginx 普通 API 限流返回 503 的问题。
- `fetchInterviewSessions(limit)` 增加同 limit 并发请求合并，Dashboard、History 和后续复用该接口的入口不会同时打出重复列表请求。
- 历史记录页刷新按钮增加同步请求锁，避免 React 状态更新前的快速连点穿透。
- 修复普通页面切换时用户端 `UserApp` 反复挂载、反复校验 `/api/auth/me`，在认证检查被限流时误判未登录并跳转 `/login` 的问题。
- 用户端改为稳定挂载，Dashboard、面试配置、历史记录等路由切换不会重新创建整套用户应用状态。
- `/api/auth/me` 只有 401 才表示未登录；429、503 等临时失败不再被当成登出。
- 被动进入登录页时不再自动调用 `/api/auth/logout`，避免正常路由切换导致 logout 风暴。
- 登录页和无有效浏览器会话时不发送 presence heartbeat。
- Nginx 普通 `/api/` 限流从 `30r/m burst=10` 调整为 `120r/m burst=30`，登录/注册继续使用严格 auth 限流，`auth/me` 与 `auth/logout` 使用普通 API 限流；限流响应码改为更准确的 `429`。
- 修复 `/api/auth/me` 遇到 429、502 或网络错误后，用户端永久停留在 loading 的问题；临时失败现在会自动退避重试，并提供手动重新校验入口。
- 用户端启动时改为始终以 HTTP-only cookie 的 `/api/auth/me` 校验结果为准，`sessionStorage` 只作为辅助标记，不再阻止有效 cookie 用户进入系统。
- `getMe()`、`getAdminMe()`、常用面试配置资源请求增加并发合并，降低 Dashboard、Setup 和历史页切换时的瞬时请求量。
- heartbeat 改为检查响应状态，并加最小发送间隔；401 会进入统一登录失效流程，429/5xx 不再影响主界面。
- Chat stream 遇到 401 时不再静默结束空回复，而是触发统一登录失效处理。
- Nginx 增加轻量 `state` 限流桶，单独承载 `/api/auth/me`、`/api/auth/logout` 和 `/api/presence/heartbeat`，避免状态类请求污染普通 API 限流。
- 后端 SPA fallback 对未匹配的 `/api/...` GET 请求返回 JSON 404，不再返回 `index.html`。

影响：

- 不改变数据库结构、用户数据、面试记录、Agent 流程和 Docker 服务数量。
- 减少重复 SQLite 查询、认证检查和 Nginx 错误日志，对小服务器资源消耗更友好。
- 真正异常高频请求仍会被限流。
- 临时网络抖动或部署层限流不会再被误判为用户登出，用户可等待自动重试或手动重新校验。

## v1.10.0

主题：后台监控与规范路由。

### 前端路由状态回退修复

- 修复登录后从 Dashboard 进入面试配置、历史记录等页面时，页面闪回 Dashboard 的问题。
- 根因是登录后的异步认证回调仍使用页面首次挂载时的旧 pathname，用户快速切换路由后会被旧回调重新导航回 Dashboard。
- 路由解析改为优先使用最新 pathname，并抽出 `resolveAuthenticatedUserView` 测试，确保已登录用户的当前 URL 优先于旧的内部 fallback 状态。

影响：

- 不改变接口、数据库、认证方式、Agent 流程和部署方式。
- 修复只影响前端路由状态同步，避免顶层页面和资源页面被旧异步认证回调覆盖。

### 前端路由第一阶段底座

- 普通用户端保持单页面应用模式，不改成多页面应用；先引入 React Router 作为客户端路由底座。
- 新增统一路由常量和路径映射测试，覆盖登录、工作台、面试配置、个人信息、历史记录、AI 总结和管理员入口。
- 顶层用户页面切换同步到稳定 URL，例如 `/dashboard`、`/setup`、`/profile`、`/history`、`/insights`。
- 管理员后台从手写 `window.history` 切换到 React Router 导航，继续保留 `/admin/login` 与 `/admin` 独立入口。
- 面试中会话和历史详情资源路由暂不迁移，后续再按 `/interview/:sessionId`、`/history/:sessionId` 做第二阶段/第三阶段接入。

影响：

- 不改变后端接口、数据库、Agent 流程、管理员认证模型和部署容器结构。
- 新增前端运行时依赖 `react-router-dom`，生产依赖审计结果为 0 个漏洞。
- 用户刷新顶层页面时可以保留对应入口位置；面试聊天页仍沿用当前内部状态，避免影响中断、恢复和自动落库流程。

### 前端顶层路由第二阶段

- 将用户端和管理员端顶层入口接入 React Router 的 `Routes` / `Route` 渲染结构。
- 新增用户顶层路由配置和管理员路由配置，避免路径散落在组件里手写判断。
- `/login`、`/dashboard`、`/setup`、`/profile`、`/history`、`/insights` 由路由表统一挂载到现有用户应用。
- `/admin/login` 和 `/admin` 由管理员路由表统一挂载到管理员应用。
- 根路径和未知路径走明确 fallback：有浏览器会话时进入 `/dashboard`，否则进入 `/login`。

影响：

- 不改变接口、数据库、认证 cookie、面试流程、管理员权限和部署方式。
- 为后续 `/interview/:sessionId`、`/history/:sessionId` 资源路由迁移留下清晰入口。
- 面试聊天仍保持内部状态管理，避免在第二阶段影响中断/恢复/自动落库逻辑。

### 前端资源路由第三阶段

- 新增 `/interview/:sessionId` 面试会话路由，新建面试和继续中断面试后会进入带 sessionId 的 URL。
- 刷新 `/interview/:sessionId` 时，通过已有会话详情接口重建聊天上下文；已结束会话会自动转到历史详情页。
- 新增 `/history/:sessionId` 历史详情路由，历史列表点击记录后 URL 会表达当前查看的具体面试记录。
- 历史详情删除后回到 `/history`，批量删除当前详情记录时也会清理对应资源 URL。
- 监控 heartbeat 改为按当前路由派生页面状态，避免资源路由切换后继续上报旧的聊天状态。

影响：

- 不新增后端接口、数据库字段或 Docker 服务，复用现有 `GET /api/sessions/{id}` 与 `POST /api/sessions/{id}/resume`。
- 资源消耗只增加用户访问资源 URL 时的一次会话详情读取，不引入轮询或常驻连接。

- 聊天内容从纯文本改为 Markdown 渲染。

影响：

- 当前不运行用户代码，因此不会引入代码执行安全风险。

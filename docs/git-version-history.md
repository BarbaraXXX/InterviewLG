# Git 版本提交记录

本文档用于记录项目每次关键 git 版本提交的主要内容，方便后续溯源、复盘和个人总结。

记录原则：

- 重点记录功能变化、架构变化、部署影响、数据/安全/资源影响。
- 不逐字复制 commit message，而是记录“为什么改、改了什么、影响什么”。
- 小修复可以归入最近的未发布记录；正式打版本时再整理到对应版本。
- 后续每次完成较完整的功能、修复或版本发布后，应同步更新本文档。

## v1.8.0

主题：语音输入转写与麦克风选择。

### 语音输入转写

- 面试聊天输入区新增语音输入入口，用户可录音后转写为文本。
- 转写结果只回填输入框，不自动发送，用户可以检查和修改后再提交。
- 后端新增 `/api/speech/transcribe`，统一做登录校验、限流、音频类型校验、大小限制和时长限制。
- 新增可替换的语音转写 Provider 抽象，默认关闭；配置外部 STT 服务后才会实际调用。
- 新增阿里云 DashScope 文件转写 Provider：后端将音频临时上传 OSS，生成短期签名 URL 后调用 Paraformer 识别，并在完成后删除临时对象。
- 增加 `SPEECH_KEEP_TEMP_OBJECTS` 调试开关，便于本地排查浏览器录音文件内容；默认关闭，正式环境仍会删除临时音频。
- 前端新增麦克风输入源选择，避免浏览器默认选择虚拟麦克风或错误设备导致静音录音。
- 录音时展示实时音量条、当前麦克风和输入状态，便于用户确认是否真正采集到声音。
- 对明显静音的录音在前端直接拦截，不再上传后端或调用外部语音识别服务。
- 语音音频不长期保存，日志只记录大小、时长和调用状态，不记录音频内容或转写全文。

影响：

- 服务器不本地运行语音模型，主要资源消耗转移到外部 STT 服务。
- 前端音量检测只在录音期间运行，停止录音或离开页面后会关闭麦克风音轨和 AudioContext。
- 新增 `python-multipart`、`dashscope`、`oss2` 直接依赖，用于处理音频 multipart 上传、阿里云语音识别和 OSS 临时对象。
- 未配置语音服务时不影响键盘输入和现有面试流程。

## v1.7.0

主题：工程规范、Agent 图结构与内容渲染增强。

### 代码规范底座

- 增加 `CONTRIBUTING.md`，记录开发检查、前端/后端验证方式、部署前关注点。
- 增加 `scripts/check.sh`，提供统一的本地检查入口。
- Python 子项目启用 ruff import 排序规则，并统一 ruff format 配置。
- 前端加入 Prettier 配置和 `format` / `format:check` 命令。
- CI 增加 `develop` 分支触发，并补充前端 lint/build 检查。
- 修复前端上下文占用初始化的 React Hooks lint 问题，避免组件卸载后继续写状态。
- 进一步统一 Python/Node 版本规范：Python 基线为 3.12，前端 Node 推荐 22.13+。
- 增加 `.python-version`，让本地 Python 版本选择更明确。
- 增加 `docs/release-checklist.md`，记录正式发布与部署前检查项。
- 增加 `docs/code-style.md`，记录 Python、前端、API、数据库、Agent、RAG 和日志规范。
- 调整 `.gitignore`，允许追踪必要规范类文档，同时继续避免提交普通 docs 草稿。

影响：

- 不影响服务器运行时资源。
- 后续提交前可以用统一脚本检查主要质量问题。
- 暂未强制全仓库格式化，避免一次性产生大量机械 diff。
- 版本记录与发布检查更容易长期维护。

验证：

- `bash scripts/check.sh` 通过。

### Markdown 与数学公式渲染增强

- 前端 Markdown 渲染增加数学公式支持。
- 支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。
- 增加 GFM 能力，包括表格、任务列表、删除线、自动链接等。
- KaTeX 配置为容错模式，避免模型输出不完整公式时导致整条消息渲染失败。

影响：

- 前端资源包增加 KaTeX 字体资源。
- 不增加后端 CPU/内存压力。

验证：

- 前端构建通过。
- 页面手动验证数学公式渲染正常。

### 手撕题代码模板修复

- 修复手撕题在切换语言后 starter code 不匹配的问题。
- 后端保存完整 `starter_code_map`，前端根据当前语言选择对应模板。
- 避免用户已经编辑的代码被语言切换误覆盖。

影响：

- 提升手撕题编辑体验。
- 不改变代码执行逻辑，因为当前系统仍不运行用户代码。

### Agent 图结构控制流调整

- 将 Agent 图从简单 interviewer/tools 结构调整为更明确的控制流。
- 新增上下文准备与回合路由节点，降低后续阶段控制复杂度。
- 保留工具调用能力，为 RAG、手撕、后续流程控制继续扩展。

影响：

- 面试流程更容易演进。
- 对已有接口和前端使用方式无明显破坏。

## v1.5.0

主题：上下文、记忆系统与上下文爆炸控制。

主要内容：

- 增加上下文 token 占用统计。
- 前端展示当前上下文使用比例，便于判断上下文是否接近预算。
- 增加会话级长期记忆：按 topic 完成情况生成单场面试摘要。
- 增加用户级长期偏好记忆：从历史面试 topic summary 中提炼用户偏好与能力倾向。
- 增加上下文压缩机制，降低长面试流程导致上下文过长的风险。
- 将上下文预算调整为按 256k 上限设计，兼顾通用模型兼容、成本和注意力分散问题。

影响：

- Agent 输入结构更规范。
- 长面试稳定性提高。
- 额外摘要会增加少量 LLM 调用，但比无限增长上下文更可控。

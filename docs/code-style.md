# 代码规范

本文档记录当前项目的轻量代码规范。目标不是引入大型工程体系，而是让后续功能迭代更容易维护、部署和排错。

## 1. 基础原则

- 默认在 `develop` 分支开发。
- 功能改动、格式化改动、数据导入改动尽量分开提交。
- 不提交运行时数据、sqlite、日志、`.env`、构建产物、缓存文件。
- 服务器资源按 2 核 2G 设计，避免把非核心任务放到服务器上执行。
- 用户数据安全优先关注：
  - 网站不被劫持；
  - 数据不泄露；
  - 日志和部署过程不暴露敏感信息。

## 2. Python 规范

适用目录：

- `interview-agent`
- `interview-vectordb`
- `interview-tester`

约定：

- Python 基线版本为 `3.12`。
- 使用 `uv` 管理依赖和运行命令。
- 使用 `ruff check` 做静态检查。
- 使用 `ruff format` 做格式化，但全量格式化需要单独提交。
- 新增公共函数优先补测试。
- 异步代码避免在请求处理里做长时间阻塞任务。

常用检查：

```bash
uv run ruff check src tests
uv run pytest
```

## 3. 前端规范

适用目录：

- `interview-agent/web`

约定：

- Node.js 推荐 `22.13+`。
- 使用 TypeScript、ESLint、Prettier。
- UI 组件尽量复用已有布局和主题变量。
- 不在组件里写散落的接口字段定义，优先复用 `api.ts` 中的类型。
- 重要用户流程改动必须跑 `npm run build`。
- 新增页面需要考虑浅色/深色主题。
- 内容区域需要考虑长文本、Markdown、代码块、表格、公式溢出。

常用检查：

```bash
npm run lint
npm run build
```

## 4. API 规范

- 后端接口入参和返回值优先使用 Pydantic model。
- 前端请求函数集中放在 `api.ts`。
- 改接口时同步更新：
  - 后端 model；
  - 前端类型；
  - 后端测试；
  - 必要的前端调用逻辑。
- 不在接口中返回不必要的敏感字段。
- 批量删除、历史记录、简历等用户数据接口必须校验当前用户所有权。

## 5. 数据库规范

- SQLite 数据路径必须来自配置或运行时数据目录，不写死到包安装目录。
- 新增表或字段必须通过幂等迁移处理。
- 迁移函数允许重复执行，不应破坏已有生产数据。
- 用户账号、面试历史、简历数据属于生产数据，部署时不得直接覆盖。
- RAG、题库等可再生成数据优先作为独立 sqlite 成品部署。

## 6. Agent / Prompt / State 规范

- Prompt 改动必须说明影响哪个阶段或工具调用。
- `InterviewState` 字段变更必须有测试。
- StageController 的职责是控制阶段推进，不应只靠关键词硬切换。
- Tool 新增必须明确：
  - 何时调用；
  - 何时不能调用；
  - 调用后如何影响状态；
  - 前端是否需要响应。
- 用户主动要求调整流程时，状态控制应尽量尊重用户意图，同时保证最终能回到合理流程。

## 7. RAG / 题库数据规范

- 数据分层：
  - 原始数据；
  - 生成数据；
  - 人工审核或确认数据；
  - sqlite 成品数据。
- 服务器部署优先上传 sqlite 成品。
- 不在服务器上做大规模抓取、清洗、embedding 或 LLM 生成。
- 数据结构变化要同步更新 schema、导入脚本和测试。
- 题库题面来源要注意版权和使用边界，当前优先使用自建题面和人工/LLM 生成内容。

## 8. 日志规范

- 日志保留流程状态、错误原因、耗时、调用结果摘要。
- 不打印 API key、Cookie、Authorization header。
- 不打印完整简历和完整面试对话。
- 用户可识别信息尽量只保留必要字段，例如 username/session_id。
- 时间统一按北京时间输出。

## 9. 提交规范

建议提交粒度：

- 一个功能一个提交；
- 一个 bugfix 一个提交；
- 格式化单独提交；
- 数据文件更新单独提交；
- 版本发布单独提交。

提交前检查：

```bash
git diff --check
bash scripts/check.sh
```

如果当前环境无法访问默认 uv 缓存，可以使用隔离缓存：

```bash
ISOLATED_UV_CACHE=1 bash scripts/check.sh
```

正式版本发布前同步更新：

- 前端版本展示；
- 前端版本更新记录；
- `docs/git-version-history.md`；
- git tag。
